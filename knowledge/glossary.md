# Glossary

Definitions as used in this guide. For the complete list of Ditto terms, see the [Ditto glossary](https://docs.ditto.live/home/glossary).

| Term | Definition |
|---|---|
| **ADVISE** (SDK 5.1+) | A DQL prefix that returns index recommendations for a statement without executing it. `ADVISE AND PROVISION` also creates the suggested indexes. See [ADVISE (SDK 5.1+)](../best-practices/indexing-and-performance.md#advise-sdk-51). |
| **Attachment** | Binary data (photos, PDFs, audio) referenced from a document field of type `ATTACHMENT` by a token. The token syncs with the document; the bytes (blob) are transferred only when a device fetches them. See [Attachments](../best-practices/attachments.md). |
| **AttachmentFetcher** | The object returned by `ditto.store.fetchAttachment()`. It reports progress through events; `stop()` cancels a fetch in progress. See [Fetching Attachments](../best-practices/attachments.md#fetching-attachments). |
| **Authentication webhook** | An HTTP service you operate that validates a user's token for Ditto Server and returns the user ID, session lifetime, and permissions. See [Authentication in Production](../best-practices/security.md#authentication-in-production). |
| **Backpressure** | Control over when the next observer result is delivered, so that slow work in your code merges intermediate results instead of queuing them. Each SDK provides it differently, for example `registerObserverWithSignalNext` in Flutter and JavaScript and `handlerWithSignalNext:` in Swift (SDK 5.1+). See [Backpressure (SDK 5.1+)](../best-practices/observers.md#backpressure-sdk-51). |
| **Big Peer** | The former name of Ditto Server. |
| **Collection** | A named group of documents, similar to a table. A collection exists as soon as a document is written to it. |
| **Commit ID** | A device-specific, increasing number returned in `QueryResult.commitID` for local writes. Comparing it with a peer's `synced_up_to_local_commit_id` tells you whether that peer has the write. See [Monitoring Sync Status](../best-practices/sync-and-subscriptions.md#monitoring-sync-status). |
| **Composite index** (SDK 5.1+) | An index over several fields in order, for example `(status, createdAt DESC)` (on SDK 5.1.0, keep all keys in one direction; see [Known Issues in SDK 5.1.0](upgrading.md#known-issues-in-sdk-510)). See [Creating Indexes](../best-practices/indexing-and-performance.md#creating-indexes). |
| **COUNTER** | A CRDT type for integers that combines increments and decrements from all devices. Changed with `APPLY ... INCREMENT BY` or `RESTART`. See [Counters](../best-practices/data-modeling.md#counters). |
| **CRDT** | Conflict-free replicated data type: a data structure whose concurrent changes on different devices merge deterministically without a coordinator. Every field in a Ditto document is stored as a CRDT. See [CRDT Types and Merge Behavior](crdt-types.md). |
| **Database ID** | The UUID that identifies a Ditto database. All peers that sync together use the same Database ID. Copy it from the Ditto Portal, or choose your own UUID for a small-peers-only deployment. |
| **Differ** | A class that compares successive observer results by `_id` and reports insertions, deletions, updates, and moves (`Differ` in Flutter and JavaScript, `DittoDiffer` in Kotlin and Swift). See [Diffing Results](../best-practices/observers.md#diffing-results). |
| **Ditto Server** | The optional server-side cluster, hosted by Ditto or run by you, that Small Peers reach over WebSocket. It connects separate meshes, handles authentication, and integrates with backend systems. Formerly called Big Peer. |
| **Document** | A JSON-like object in a collection, identified by its immutable `_id`. Each field merges according to its CRDT type. |
| **DQL** | Ditto Query Language, the SQL-like language for reading, writing, and observing documents. See [DQL Fundamentals](../best-practices/dql.md#dql-fundamentals). |
| **Edge device** | A device at the edge of the network, such as a phone, tablet, or kiosk, that runs a Small Peer. |
| **EVICT** | A DQL statement that removes documents from the local store only. The removal is not propagated to other peers, and no tombstone is created. See [EVICT](../best-practices/deletion-and-storage.md#evict). |
| **Eviction** | Removing documents from the local store only, with `EVICT`. Eviction does not sync to other peers. See [EVICT](../best-practices/deletion-and-storage.md#evict). |
| **Expiration handler** | The callback registered with `ditto.auth.setExpirationHandler()` that logs the device in to Ditto Server when it needs to authenticate and when credentials are about to expire. See [Authentication](../best-practices/setup-and-lifecycle.md#authentication). |
| **EXPLAIN / PROFILE** | DQL prefixes that show a statement's query plan without running it (`EXPLAIN`) or run it and report timings per step (`PROFILE`). See [EXPLAIN and PROFILE](../best-practices/indexing-and-performance.md#explain-and-profile). |
| **Frozen copy** | A document that remains on a device after no active subscription on that device matches it any more, because the document changed or a subscription was cancelled (a sync scope set on the sending device has the same effect). Local queries still return it, but it no longer receives updates or deletions. See [Multi-hop relay](../best-practices/sync-and-subscriptions.md#multi-hop-relay). |
| **Husk document** | The result of a deletion on one device merging with a concurrent update on another: the document is not deleted; the updated fields keep their values (or become `null` if the deletion was later); all other fields are missing. See [Husk documents](../best-practices/deletion-and-storage.md#husk-documents). |
| **Hybrid Logical Clock (HLC)** | The clock Ditto uses to decide which of two concurrent register writes is the latest. |
| **Index** | A per-device data structure that lets queries find documents without scanning the whole collection. Indexes persist, but are not synced. See [Indexing and Query Performance](../best-practices/indexing-and-performance.md). |
| **INITIAL DOCUMENTS** | An `INSERT` form for default data that every peer may create independently; existing documents are never overwritten. See [Default Data with INITIAL Documents](../best-practices/data-modeling.md#default-data-with-initial-documents). |
| **JOIN** (SDK 5.1+) | Combining documents from several collections in one local `SELECT`. Not allowed in subscriptions; the inner collection needs an index or an `_id` join. See [Joining Collections (SDK 5.1+)](../best-practices/dql.md#joining-collections-sdk-51). |
| **MAP** | A CRDT type for objects whose keys merge independently (add-wins). Objects are stored as maps by default. See [Arrays and Maps](../best-practices/data-modeling.md#arrays-and-maps). |
| **Mesh** | The network of peers connected to each other over peer-to-peer transports, optionally bridged to Ditto Server. |
| **MISSING** | The state of a field that is absent from a document, distinct from a field whose value is `null`. Test it with `IS MISSING`. See [MISSING and NULL](../best-practices/dql.md#missing-and-null). |
| **Multi-hop relay** (multi-hop sync) | Relaying documents through intermediate peers that are not directly connected to each other. A peer can relay only documents it stores itself. See [Multi-hop relay](../best-practices/sync-and-subscriptions.md#multi-hop-relay). |
| **Observer** (store observer) | A live local query registered with `ditto.store.registerObserver()` that delivers a new result whenever matching local data changes. Observers never cause data to sync. See [Observing Changes](../best-practices/observers.md). |
| **Offline license token** | A token issued by Ditto that activates an instance in small-peers-only mode. `ditto.sync.start()` throws until it is set; the local store works without it. See [Initializing Ditto](../best-practices/setup-and-lifecycle.md#initializing-ditto). |
| **Peer** | An instance of the Ditto SDK, or Ditto Server, that participates in sync. |
| **REGISTER** | A CRDT type that holds a single value (a scalar, an array, or an object declared as `REGISTER`); concurrent writes resolve by last-writer-wins. See [CRDT Types and Merge Behavior](crdt-types.md). |
| **RETURNING** (SDK 5.1+) | A clause that returns the affected documents from `INSERT`, `UPDATE`, `DELETE`, or `EVICT`. See [RETURNING (SDK 5.1+)](../best-practices/dql.md#returning-sdk-51). |
| **Shared key** | The `privateKey` that all peers of a small-peers-only deployment use to authenticate each other and encrypt traffic. See [Small-Peers-Only Deployments](../best-practices/security.md#small-peers-only-deployments). |
| **Small Peer** | An instance of the Ditto SDK embedded in an application. |
| **Soft delete** | Marking a document as deleted with an ordinary `UPDATE` of a flag such as `isDeleted`, instead of `DELETE`. See [Soft Delete](../best-practices/deletion-and-storage.md#soft-delete). |
| **Strict mode** | The `DQL_STRICT_MODE` system parameter (default `false`). When `true`, undeclared objects are stored as registers and MAP, COUNTER, and ATTACHMENT fields must be declared in every statement. See [Strict Mode](../best-practices/data-modeling.md#strict-mode). |
| **Subscription** | A `SELECT * FROM <collection> [WHERE ...]` query registered with `ditto.sync.registerSubscription()` that tells connected peers which documents to send to this device. See [Sync and Subscriptions](../best-practices/sync-and-subscriptions.md). |
| **Sync scope** | A per-collection setting (`USER_COLLECTION_SYNC_SCOPES`) that limits where a device sends its documents. See [Sync Scopes](../best-practices/sync-and-subscriptions.md#sync-scopes). |
| **System parameter** | A setting passed in `DittoConfig.systemParameters` (SDK 5.2+), read with `SHOW`, and changed at run time with `ALTER SYSTEM`. Settings are not persisted. See [System Parameters Reference](system-reference.md#system-parameters-reference). |
| **Tombstone** | The marker that `DELETE` leaves behind so that the deletion syncs to other peers. Tombstones expire after a TTL (7 days by default on Small Peers, set with `TOMBSTONE_TTL_HOURS`) and are then removed by reaping. See [DELETE and Tombstones](../best-practices/deletion-and-storage.md#delete-and-tombstones). |
| **Transaction** | A group of DQL statements executed atomically against the local store with `ditto.store.transaction()`. See [Transactions](../best-practices/transactions.md). |
| **Transport** | A connection technology used for sync: Bluetooth LE, peer-to-peer Wi-Fi (AWDL, Wi-Fi Aware), LAN, and WebSocket. See [Transport Configuration](../best-practices/setup-and-lifecycle.md#transport-configuration). |
| **Virtual collection** | A local-only collection in the `system:` namespace that describes the device and its query engine, such as `system:system_info` or `system:indexes`. Read-only, except that `DELETE FROM system:request_history` clears the request history. See [System Virtual Collections](system-reference.md#system-virtual-collections). |
| **Zombie data** | Deleted data that reappears when a device that missed the deletion reconnects after the tombstones have expired. See [Tombstone TTL and reaping](../best-practices/deletion-and-storage.md#tombstone-ttl-and-reaping). |
